# Smart Organize V2 專利提案草稿

## 1. 與本提案相關的傳統做法

當一個 3D 物件由大量零件組成時（例如一張椅子可能包含椅腳、椅座、椅背、扶手等數十個零件），使用者需要為每個零件命名並將相關零件歸入群組，以便後續的編輯、管理與匯出。

**傳統做法為人工手動操作：**

使用者在 3D 編輯器中逐一點選每個零件，手動輸入名稱（如「Left Front Leg」），再手動建立群組並拖曳零件歸入。當零件數量較少時尚可應付，但當零件數量達到 20 個以上，此流程極為耗時且容易出錯（如命名不一致、遺漏零件、分組邏輯不統一）。

```
使用者逐一操作：

  零件 1 → 手動命名 → 手動歸入群組
  零件 2 → 手動命名 → 手動歸入群組
  零件 3 → 手動命名 → 手動歸入群組
  ...
  零件 N → 手動命名 → 手動歸入群組
```

## 2. 傳統做法中的問題

### 問題一：耗時且不可擴展

人工命名與分組的時間隨零件數量線性增長。一個包含 30 個零件的模型可能需要數十分鐘的手動操作。在需要批次處理多個模型的工作場景中，此瓶頸尤為嚴重。

### 問題二：命名不一致

不同使用者（甚至同一使用者在不同時間）對相同類型的零件可能給予不同的名稱（如「Leg」vs「Support」vs「Stand」），導致後續搜尋、篩選與自動化處理困難。

### 問題三：分組依賴人為判斷

使用者必須自行決定哪些零件應歸為同組。對於結構複雜的模型，使用者可能遺漏關聯性（例如四個椅腳應歸為同組），或做出不合理的分組。

---

## 3. 本提案所做的改變

本提案利用視覺語言模型（VLM）自動完成零件命名與分組，並透過以下三項技術確保在大量零件時仍維持高準確度：

### 改變一：以編號標註截圖輔助 VLM 辨識零件

從 3D 場景中擷取多角度截圖，其中色塊截圖（每個零件以不同顏色渲染）上透過 2D 圖形合成技術，在每個零件的視覺中心位置疊加數字編號標籤（如 1、2、3）。VLM 直接讀取截圖上的編號來識別零件，**不需要從相似的顏色中分辨零件**，即使零件數量很多也不會混淆。

### 改變二：兩階段推論架構

將 VLM 的任務拆分為兩個階段，降低每次推論的複雜度：

- **第一階段（結構辨識）**：僅輸入原始紋理截圖，讓 VLM 辨識物件類型與主要結構區域（如「這是一張辦公椅，有底座、椅座、椅背、扶手」）。此階段不涉及任何零件資訊，任務簡單明確。
- **第二階段（命名與分組）**：將第一階段的結構描述作為上下文，連同編號標註截圖一起送入 VLM。VLM 已知物件結構，只需將每個編號零件對應到已知的結構區域並命名。

### 改變三：空間位置提示

利用 3D 模型的幾何資訊，自動計算每個零件在模型中的相對空間位置（如「#1, #2, #3 位於模型底部且彼此接近」），以文字描述的形式提供給 VLM 作為分組參考。空間上接近的零件更可能屬於同一群組，此提示大幅提升分組的合理性。

## 4. 詳細實施方法

### 整體流程

```
┌─────────────────────────────────────────────────────────┐
│                    前端處理                              │
│                                                         │
│  ① 從 3D 場景擷取原始紋理截圖（3 個固定角度）             │
│  ② 依零件數量決定色塊截圖角度數（≤15:3 / 16-30:5 / >30:6）│
│  ③ 擷取色塊截圖（每個零件以不同顏色渲染）                  │
│  ④ 在色塊截圖上疊加編號標籤（Canvas 2D 合成）             │
│  ⑤ 計算各零件的空間位置描述                               │
│  ⑥ 建立編號→零件ID對照表                                 │
└────────────────────────┬────────────────────────────────┘
                         │ 單次 API 請求
                         ▼
┌─────────────────────────────────────────────────────────┐
│                    後端處理                              │
│                                                         │
│  ⑦ 第一階段 VLM 呼叫                                    │
│     輸入：原始紋理截圖（3 張）                            │
│     輸出：物件類型 + 結構區域列表                         │
│     (失敗時以預設值繼續，不中斷流程)                       │
│                                                         │
│  ⑧ 第二階段 VLM 呼叫                                    │
│     輸入：原始紋理截圖 + 編號標註色塊截圖                  │
│          + 第一階段結構描述                               │
│          + 空間位置提示                                   │
│          + 編號→ID 對照表                                │
│     輸出：每個零件的名稱與群組                            │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│                    前端套用                              │
│                                                         │
│  ⑨ 根據結果重新命名各零件                                │

│  ⑪ 同步更新 3D 場景樹                                   │
```

### 空間位置提示的計算

1. 取得 3D 模型的整體包圍盒（Bounding Box）
2. 計算每個零件的包圍盒中心座標
3. 將座標正規化至 [0, 1] 區間（相對於整體包圍盒）
4. 根據正規化座標產生語義描述（如 upper-left region、bottom region）
5. 將空間上彼此接近的零件合併描述，標註「close together」

**輸出範例：**
```
#1, #2, #3: bottom region, close together
#4: center region
#5, #6: upper-left region
```

### 兩階段推論的設計

**第一階段（僅接收原始紋理截圖）：**
```
輸入：3 張不同角度的原始紋理截圖
任務：辨識物件類型、列出主要結構區域
輸出：{"object": "office chair", "regions": ["base", "seat", "backrest", "armrests"]}
```

**第二階段（接收全部資訊）：**
```
輸入：原始紋理截圖 + 帶編號的色塊截圖 + 第一階段結構描述 + 空間提示 + 編號對照表
任務：為每個編號零件命名並分組（可參考但不受限於第一階段的結構區域）
輸出：[{"id": "part_abc", "name": "Left Armrest", "group": "Armrests"}, ...]
```

第一階段失敗時，系統以預設值（物件類型 = 未知、結構區域 = 空）繼續執行第二階段，確保流程不會中斷。

### 動態拍攝角度

為確保零件數量多時每個零件至少在一個角度中可見，本提案根據零件數量動態增加色塊截圖的拍攝角度：

| 零件數量 | 角度數 | 視角配置 |
|---------|--------|---------|
| ≤ 15    | 3      | 前右、後左、上側 |
| 16–30   | 5      | + 底部、正面 |
| > 30    | 6      | + 正上方俯視 |

原始紋理截圖始終維持 3 個角度，以控制第一階段的推論成本。
